模型部署是将训练好的大语言模型投入实际应用的关键环节。本章介绍常见的部署方案和工具。

## 1.1 为什么需要专门的部署方案

训练框架（如 PyTorch）直接推理存在以下问题：

| 问题 | 描述 |
| :--- | :--- |
| **吞吐量低** | 单次只能处理一个请求 |
| **显存利用率低** | 无法有效利用 GPU 资源 |
| **延迟高** | 缺乏推理优化 |
| **无并发支持** | 不支持多用户同时访问 |

## 1.2 主流部署方案对比

| 方案 | 特点 | 适用场景 |
| :--- | :--- | :--- |
| **vLLM** | 高吞吐、PagedAttention | 生产环境、高并发 |
| **SGLang** | 高性能、结构化生成 | 复杂推理、JSON输出 |
| **LMDeploy** | 国产模型优化、多模态 | InternLM、InternVL |
| **Ollama** | 简单易用、本地部署 | 个人使用、快速体验 |
| **llama.cpp** | CPU推理、低资源 | 边缘设备、无GPU环境 |
| **TGI** | HuggingFace官方、功能全面 | 企业级部署 |

## 1.3 部署架构

```
用户请求 → API网关 → 推理服务 → 模型
                ↓
           负载均衡（多实例）
```

## 1.4 关键性能指标

| 指标 | 说明 |
| :--- | :--- |
| **吞吐量（Throughput）** | 单位时间处理的请求数 |
| **延迟（Latency）** | 单个请求的响应时间 |
| **首Token延迟（TTFT）** | 生成第一个token的时间 |
| **每Token延迟（TPOT）** | 生成每个token的平均时间 |
